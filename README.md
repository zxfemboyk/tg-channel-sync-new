# Сайт с синхронизацией Telegram-канала

Сайт показывает ленту постов (текст + фото/видео) из твоего Telegram-канала
и обновляется в реальном времени — без перезагрузки страницы.

## Как это работает

- Бот (Telegraf) добавлен администратором в твой канал и получает все новые посты.
- Сервер (Express) скачивает медиа, сохраняет пост и рассылает его всем открытым
  вкладкам сайта через WebSocket.
- Фронтенд — обычная HTML-страница, которая сразу показывает новый пост, как
  только он приходит.

## Шаг 1. Создать бота

1. Открой в Telegram **@BotFather**.
2. Отправь `/newbot`, придумай имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...` — он понадобится дальше.

## Шаг 2. Добавить бота в канал

1. Открой настройки своего канала → **Администраторы** → **Добавить администратора**.
2. Найди своего бота и добавь его. Права на публикацию постов ему не нужны —
   достаточно, чтобы он был в списке админов (тогда он видит все посты канала).

## Шаг 3. Запустить локально (проверить, что всё работает)

```bash
cd tg-channel-sync
cp .env.example .env
# открой .env и вставь свой BOT_TOKEN
npm install
npm start
```

Открой `http://localhost:3000` — сайт пустой. Опубликуй пост в канале —
он появится на странице в течение секунды.

## Шаг 4. Бесплатный деплой на Render

1. Залей проект на GitHub (приватный репозиторий тоже подойдёт).
2. Зайди на [render.com](https://render.com), зарегистрируйся (можно через GitHub).
3. **New +** → **Web Service** → выбери свой репозиторий.
4. Настройки:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free
5. В разделе **Environment** добавь переменную `BOT_TOKEN` со значением токена
   от BotFather (и, если нужно, `CHANNEL_USERNAME`).
6. Нажми **Create Web Service** — через пару минут сайт будет доступен по
   адресу вида `https://твой-сайт.onrender.com`.

**Важно про бесплатный тариф Render:** сервис "засыпает" после ~15 минут без
запросов и просыпается ~30–60 секунд при следующем заходе. Пока сайт спит,
бот всё равно не получает посты (процесс не работает). Если нужна
безостановочная работа 24/7, либо возьми платный тариф Render ($7/мес),
либо используй сервис вроде UptimeRobot, который будет пинговать сайт каждые
5 минут, не давая ему уснуть.

## Удаление постов (пост удалили в канале → пропадает с сайта)

Telegram не присылает ботам прямое уведомление «пост удалён», поэтому сайт
сам периодически (раз в 3 минуты) незаметно проверяет, существуют ли
сохранённые посты ещё в канале, и убирает те, которых больше нет.

Чтобы это включить:

1. Найди своего бота в Telegram (по тому username, который придумывал у
   BotFather) и открой с ним личный чат.
2. Напиши ему: `/start`
3. Бот ответит тебе твоим **chat id** — числом вроде `123456789`.
4. Открой файл `.env`, найди строку `ADMIN_CHAT_ID=` и впиши туда это число:
   ```
   ADMIN_CHAT_ID=123456789
   ```
5. Сохрани файл и перезапусти сайт (`Ctrl+C` в терминале, затем снова `npm start`).

Если `ADMIN_CHAT_ID` не заполнен — сайт работает как раньше, просто не
удаляет посты вслед за каналом (в терминале будет об этом написано).

## Импорт старой истории канала

Бот видит только те посты, которые публикуются **после** того, как его
добавили администратором — старые посты он получить не может (так устроен
Telegram Bot API). Чтобы перенести старую историю, экспортируем её через
Telegram Desktop (программу для компьютера, не приложение в браузере):

1. Скачай и установи **Telegram Desktop**, если его ещё нет:
   https://desktop.telegram.org
2. Зайди в свой аккаунт, открой нужный канал.
3. Нажми на три точки (меню) в правом верхнем углу чата → **«Экспорт истории чата»**.
4. В окне экспорта оставь отмеченными: **Фотографии**, **Видеофайлы**,
   **Файлы**, **GIF** (остальное можно снять, если не нужно).
5. Снизу выбери формат **«Машиночитаемый JSON»** (machine-readable JSON) — это важно,
   обычный HTML не подойдёт.
6. Нажми **«Экспортировать»** и дождись окончания (для больших каналов может
   занять несколько минут).
7. По завершении откроется папка с экспортом — запомни её путь
   (например `C:\Users\gkiri\Downloads\Telegram Desktop\ChatExport_2026-11-09`).
8. Останови сайт, если он запущен (`Ctrl+C` в терминале).
9. В терминале, в папке проекта, выполни:
   ```bash
   npm run import -- "C:\Users\gkiri\Downloads\Telegram Desktop\ChatExport_2026-11-09"
   ```
   (вставь свой путь к папке экспорта вместо примера, кавычки оставь, если
   в пути есть пробелы)
10. Скрипт скопирует медиафайлы и добавит старые посты в `data/posts.json`.
    Уже существующие посты (по messageId) пропускаются, так что повторный
    запуск ничего не продублирует.
11. Запусти сайт заново (`npm start`) — старые посты появятся в ленте вперемешку
    с новыми, отсортированные по дате.

## Структура проекта

```
tg-channel-sync/
├── server/
│   ├── index.js          — сервер, бот, WebSocket, проверка удалённых постов
│   ├── store.js          — хранение постов (JSON-файл)
│   ├── media.js          — скачивание фото/видео из Telegram
│   └── importHistory.js  — импорт старой истории из экспорта Telegram Desktop
├── public/
│   ├── index.html
│   ├── style.css
│   └── script.js
├── media/          — скачанные медиафайлы
├── data/posts.json — список постов
└── .env            — токен бота (не коммитить!)
```

## Настройки (.env)

| Переменная         | Обязательна | Описание                                            |
|--------------------|-------------|------------------------------------------------------|
| `BOT_TOKEN`        | да          | токен от @BotFather                                   |
| `CHANNEL_USERNAME` | нет         | username канала без `@` — фильтр, если бот в нескольких каналах |
| `PORT`             | нет         | порт сервера (Render подставляет сам)                 |
| `ADMIN_CHAT_ID`    | нет         | твой личный chat id — включает проверку удалённых постов |

## Возможные доработки

- Пагинация / бесконечная прокрутка вместо последних 500 постов.
- Поддержка альбомов (media group) — сейчас каждое фото из альбома придёт отдельным постом.
- Хранение медиа в облаке (Cloudflare R2 / S3) вместо локального диска — полезно,
  если на Render бесплатном тарифе диск эфемерный и очищается при пересборке.
